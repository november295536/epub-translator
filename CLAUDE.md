# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

EPUB 智能翻譯系統 - Translates English EPUB books to Traditional Chinese through a model backend (`claude-cli`, `copilot-cli`, or `copilot-sdk`: the Copilot Python SDK on the installed `copilot` program). Glossary with automatic extraction, per-book brief, structural validation with retry, three output formats, Web review interface and CLI. `plan/02-improvement-plan.md` is the design record, `plan/03-acceptance-log.md` the evidence per phase. Python 3.12+ (`src/__init__.py` `require_python` stops older interpreters on import of `src`, so before any other module of `translate.py` or the app factory); POSIX only (macOS/Linux: `fcntl` locks, process groups).

```text

translate.py status
translate.py start [-b claude-cli|copilot-cli|copilot-sdk] [-m MODEL] [-w 1..20] [--retry-failed]
translate.py validate PROJECT_DIR [--mark-failed]

translate.py brief show

translate.py model show
translate.py model set [-b claude-cli|copilot-cli|copilot-sdk] [-m MODEL] [-e LEVEL] [-t SECONDS]   (at least one; does not translate)
translate.py glossary show | extract | add TERM TRANSLATION [-c CAT] [-g GENDER] [-n NOTE] | import FILE | export FILE
translate.py export [-f chinese-only|bilingual-horizontal|bilingual-vertical]   (default bilingual-horizontal)
translate.py review [--port 5000]
translate.py stats [--since TIME] [--run RUN_ID] [--json]   (summary of log/events.jsonl)
```

Backend, model, reasoning effort and call timeout are stored in the project; from the CLI `model set -b/-m/-e/-t` sets them (takes `project.lock` like `brief set`) and `start -b/-m` sets backend/model and then translates. All of them and the web `PUT …/model` go through `ProjectManager.select_model`: the project's own backend is not stored again, a new backend without a model takes its default model, a model must belong to the backend it will run with, an effort must be one of the model's levels (`ModelInfo.efforts`), a timeout an integer 30–3600; when the backend or model changes, a stored effort the new model does not take is dropped back to the default (the confirmation says so, `effort_reset_note`; an effort- or timeout-only change keeps it); refused values change nothing (`SettingError`, a `ValueError` naming the setting). Calls use `ProjectManager.call_settings()` (`CallSettings.call_args()` → `TranslationEngine` / `TermExtractor`). `glossary extract` uses the stored backend, so a Copilot-only user runs `model set -b copilot-cli` (or `copilot-sdk`; or picks a Copilot model on the web translation page) first.

## Architecture

### Pipeline
1. **Extraction** (`src/epub/extractor.py`) — reads the package (OPF, spine) with lxml; chapters as parsed XHTML.
2. **Blocks** (`src/epub/blocks.py`) — `walk_blocks`: a chapter body as blocks (block-level elements, or runs of inline content), each with an index and a whitespace-free text fingerprint.
3. **Segmentation** (`src/core/segmenter.py`) — contiguous block ranges; a block is never split. Groups to `MIN_WORDS`=300 without passing `MAX_WORDS`=500 unless one block is larger; code and tables alone. Rules (`project.segmentation`): 1 = heading alone (old projects), 2 = heading joins the following blocks (its first text block always, even past 500 words; alone only before code, a table or the chapter end), and code without a comment line is `passthrough` (no model call, exported as is).
4. **Translation** (`src/core/translator.py`) — `translate_segment` / `TranslationEngine`: text prompts get the brief at the top, the glossary and context (nearest non-code segment of the chapter before/after; with rules 2 the one before as its translation when it has one); code prompts get none of these. Protected HTML in, reply checked, at most `MAX_CALLS`=4 calls per `translate_segment` (request, one retry with the errors, one split in two halves; a requeued segment starts a new budget), the project's timeout per call (default `DEFAULT_TIMEOUT`=180 s) and its effort passed with each call. Returns a `TranslationOutcome` with typed `Issue`s; a failure writes `log/failed/<id>-<digest>.txt`. `ProjectManager.apply_outcome`: a failed outcome makes a pending segment `failed`; a translated/reviewed one keeps its text and status and only gets the issues (so `--retry-failed` does not select it).
5. **Validation** (`src/core/validation.py`) — attributes replaced by keys (`<p k="1">`; `alt`/`title`/`aria-label` stay visible to be translated); `p = protect(html); restore(p.html, p) == html`. Shared rules in `check_html` / `check_code`, used by model replies (after `check_keys` on the keyed form), by `check_segment` (review saves/approvals and `validate`, plus glossary warnings) and by the export (which also checks the chapter's blocks, so passing `validate` does not guarantee export). Structural rules block (`structure_mismatch`, `key_mismatch`, `tag_count`, `code_changed`, …); quality/glossary rules warn (`length_ratio`, `untranslated`, `term_not_applied`).
6. **Review** (`src/web/`) — side-by-side editing; a save or approval that fails the structural check is refused (422).
7. **Export** (`src/epub/exporter.py`) — ZIP written from the source EPUB that `source_epub_path` (`src/core/project.py`) resolves: the project directory's own `source.epub` (every schema 2 project has one, written at creation or by migrate), else the recorded `epub_path`, so a moved or renamed project still exports; the file opened is hash-checked against `source_sha256` (the digest recorded at creation or migration) and may not be the output; `epub_path` is not rewritten. Only translated chapters, OPF, NCX, nav (and one stylesheet for bilingual) differ; every other member keeps identical uncompressed bytes (the archive itself is rewritten). A chapter whose blocks no longer match the stored ranges/fingerprints, or a segment that fails the check, stays in the original language; the report says why. Takes `project.lock`.

### Backends (`src/llm/`)
- `LLMBackend` protocol (`base.py`); `BACKENDS` / `backend_for(name)` in `__init__.py`; project field `backend` (absent = `claude-cli`). `CLIBackend` (`cli.py`) is the only place that starts a model process per call (the SDK backend's one runtime process is started by the SDK, see `CopilotSDK`): own process group, cancel/deadline polling, killed on cancel and at interpreter exit, working directory = system temp dir, one `SYSTEM_PROMPT`.
- `ClaudeCLI` (`claude_cli.py`): `claude -p` plus `--effort LEVEL` when the request has one, plus `LEAN_FLAGS` (`--system-prompt`, no tools, no MCP, no setting sources, no session file); `CLAUDECODE` and `CLAUDE_CODE_EFFORT_LEVEL` (it overrides `--effort`) removed from the environment. The CLI ignores an unknown `--effort` value with a warning and exit 0, so only declared levels are passed. Models `sonnet` (default), `opus`, `haiku`. Error classes from output patterns (rate limit, expired login).
- `CopilotCLI` (`copilot_cli.py`): `copilot -p … [--reasoning-effort LEVEL] --output-format json --available-tools none … --experimental --plugin-dir src/llm/copilot_plugin`. The plugin's extension replaces Copilot's system prompt (read from `EPUB_TRANSLATOR_SYSTEM_PROMPT`). After each call, every reported model call must show exactly one `agent_replacement` system segment, else `BackendUnavailableError` (nothing stored; web pauses, CLI exits 1). Risks: experimental, undocumented interface and telemetry (tested with Copilot CLI 1.0.114); rate-limit messages are Copilot's documented ones, auth/refusal patterns are guesses. A level the model does not take (`Reasoning effort "…" is not supported for model …`, `… does not support reasoning effort configuration`, exit 1 before any model call) is a `BackendUnavailableError` (`EFFORT_REJECTED_MESSAGE`).
- `CopilotSDK` (`copilot_sdk.py`, Phase 12): the Python SDK `microsoft-copilot-sdk` (imported lazily in `_new_client`, the only place that creates an SDK client; a missing package or `copilot` program is a `BackendUnavailableError`). Runtime = the `copilot` on PATH, spawned over stdio (`RuntimeConnection.for_spawned_stdio(path=…)`: never the SDK's download), mode `coding-agent`, default `COPILOT_HOME` (mode `empty` or another home silently use the GitHub CLI's token: not set). One client per process (`_Runtime`: event loop in a daemon thread, started on first use, `client.start()` before every call, which brings up a new runtime when the last one died; auth checked once per client, not logged in → `AuthError`; stopped at exit by a `threading._register_atexit` hook, which runs before `concurrent.futures` shuts its executors down (the SDK's `stop()` needs them), after the turns still running were stopped and deleted their sessions (≤ 15 s, one cleanup: abort+idle 5 s, delete 10 s; then the graceful stop ≤ 10 s, else `force_stop`, the two together ≤ 20 s: at most about 35 s in all); `atexit` is the fallback). One request = one session with our own id: `session_options` (system message replaced by `SYSTEM_PROMPT`, `available_tools: []`, built-in MCP servers disabled, skills off, no custom instructions or config discovery, telemetry, infinite sessions and the cross-session store off, effort as `inference.reasoning_effort`), `send_and_wait`, reply = final assistant message, usage = summed `assistant.usage`; then `delete_session` (removes `~/.copilot/session-state/<id>/`). `complete` waits on the loop's future with cancel/deadline polling (never past the deadline; a late reply is refused); on cancel or timeout it returns at once (`CancelledError` / `TransientError`) and sets the turn's stop event: the turn is never cancelled from outside, so its cleanup always runs — it aborts the turn (`session.abort()`, waits ≤ `ABORT_WAIT_SECONDS` for idle) and deletes the session (`send_and_wait`'s own timeout leaves the turn running and billed); a stop during session creation sends no prompt. A last `finish_reason` `length` → `stop_reason='truncated'`, a filtered reply → `RefusalError` (neither observed). Error classes from copilot_cli's patterns on error text only (unknown model and refused effort observed; rate limit, login, refusal not observed); a runtime that went away (`ProcessExitedError`, EOF, "not connected") is transient. Shares `MODELS`, default model, `AUTH_HINT`, `redact` and the patterns with `copilot_cli`. Ctrl-C in the CLI reaches the runtime too (same process group): the sessions of calls in flight are then not deleted; the same holds for Ctrl-C in the terminal of a web server during a translation (pause first). The stop event and the caller's cancel are checked on entry, after the client is ready and before sending; client start/auth and the send race the stop (which the caller sets at its deadline at the latest), session creation does not (a creation given up half-way could leave a session) and is bounded by the request's timeout; abort+idle and delete have separate bounds, so a failed or hung abort still deletes; a stop before session creation deletes nothing. A failed delete of a created session is logged (`logger.warning`, session id only: CLI stderr, web server output and `log/translation_*.log`): its folder keeps prompt and reply. A runtime that dies or is killed (`kill <PID>` of `copilot --headless`) while calls run also leaves those calls' folders. A web pause reports `paused` once the cancel is set, before the turns' abort and delete finish (≤ 15 s): wait that long before stopping the server. `content_filter_triggered` is a refusal only when the last usage event has it or the reply is empty. Both Copilot backends' session folders and `~/.copilot/session-store.db` are local files; `copilot-cli` cannot keep its calls out of the store (no per-call switch in 1.0.114, `known-issues.md`), so `copilot-sdk` is the one for real books.
- Copilot models (`copilot_cli.MODELS`, a static list, also the SDK backend's): Claude `claude-sonnet-5.5` (default), `claude-sonnet-5`, `claude-opus-5.5`, `claude-haiku-5.5`, `claude-haiku-4.5`; GPT `gpt-6.2-sol`, `gpt-6.2-astra`, `gpt-6.1-sol`, `gpt-6.1-terra`, `gpt-6-sol`, `gpt-6-luna`, `gpt-6-astra`, `gpt-5.6-sol`, `gpt-5.6-luna`; Gemini `gemini-4-carbon`, `gemini-4-argon`, `gemini-4-hydrogen`, `gemini-3.8-flash`; Grok `grok-4.7`, `grok-4.6` (multipliers in the descriptions). The web selector groups models by backend and alias family (`<optgroup>`); `model show` prints one line per family.
- Effort levels per model (`ModelInfo.efforts`; `EFFORT_LEVELS` = `low…max`, `KNOWN_LEVELS` adds Copilot's `none`), from the CLIs' own validation (Claude Code 2.1.330, Copilot CLI 1.0.114; no command lists them, they can change between versions, as can Copilot's model list): the Claude backend's models, Copilot's Claude 5/5.5 and GPT models take `low, medium, high, xhigh, max` (`gpt-6-sol`, `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-luna` also `none`); Gemini `low, medium, high`; Grok `low, medium, high, xhigh`; `claude-haiku-4.5` none (nothing passed). `call_settings` uses a stored level only when the model lists it, else the default (the file keeps it until a backend/model change drops it); a value outside `KNOWN_LEVELS` (e.g. `"bogus"`) makes the project fail to load and must be corrected or removed. Known risk: high levels on slow models (Gemini) can exceed the timeout.
- No backend reports `retry_after`, so a rate limit waits `RATE_LIMIT_WAIT_SECONDS`.
- `FakeBackend` (`fake.py`) for tests; `tests/conftest.py` refuses any real model process (`run_process`) and any real SDK client (`copilot_sdk._new_client`, with a fresh `_Runtime` per test), and for the whole session puts failing `claude`/`copilot` stand-ins first on `PATH` (exit 97, inherited by every child process); other subprocesses (lock tests) are allowed.

### Runtime
- **Web task** (`src/web/tasks.py`, `TaskManager`): coordinator + workers (`MAX_WORKERS`=20) + `result_queue`; only the coordinator applies results, and it saves them (a web export first flushes the running task's saver from the request thread). `EventBroadcaster` feeds SSE: a client gets a status snapshot, then every event from when it connected (no history). Backend/model/effort/timeout/brief re-read per segment, so a switch applies to the next segment. Worker count can change on resume.
- **Run-level errors** (`src/core/runcontrol.py`): rate limit → pause, auto-resume after `retry_after` (clamped 1–3600 s) or `RATE_LIMIT_WAIT_SECONDS`=300; expired login / backend unavailable → web: pause until the user resumes; CLI: exit 1. A web pause (user or error) cancels calls in flight; their segments are queued again. A CLI rate limit stops dispatch and backoff waits; calls already running finish. Transient errors back off 5/15/45 s inside the segment's call budget. `MAX_CONSECUTIVE_UNEXPECTED`=5 unexpected failures in a row stop the run.
- **Saving**: `DebouncedSaver.maybe_save` saves when `SAVE_INTERVAL_SECONDS`=10 have passed or `SAVE_EVERY_RESULTS`=20 results wait. It is checked after each result (web also on each coordinator tick, about 1 s), so the interval is a threshold, not a durability bound: a sequential CLI run checks only after its next result. Pause (at the next tick), stop, end and failure attempt a flush; results not saved are reported. Failure logs are written only after their result is on disk.
- **Concurrency** (covers `project.json`): one in-process RLock per project (`project_mutex`) for every change and save, plus a file lock `project.lock` (`ProjectLock`, flock) held by a CLI run, a web task, migrate, export, `validate --mark-failed`, project create/delete and each web edit transaction (`TaskManager.transaction`); a locked project answers 409. `glossary.json` takes neither: glossary edits go through during a run, are not seen by it (the glossary is loaded at its start) and can overwrite each other. Edits carry a `revision`; a result computed for an older revision is dropped.
- `ProjectManager` mutations are in-memory; callers call `pm.save()` (atomic write, file mode kept).

### Run records
- **Process log** (`src/core/proclog.py`): `proclog.setup(projects_dir, name, what)` adds a `RotatingFileHandler` (5 MB × 5 backups, INFO) to the root logger: `<parent of projects dir>/logs/web.log` from `create_app`, `…/cli.log` from every CLI command (`_LoggedCommand` / `_LoggedGroup` in `translate.py`: projects dir = parent of `-p`/`PROJECT_DIR`, else `./projects`). `EPUB_TRANSLATOR_LOG_DIR` replaces the directory (`tests/conftest.py` points it at a session temp dir, so no test writes into the repository; tests of the default delete it). Start line: what (command with its parameters, values of `text`/`term`/`translation`/`note`/`gender`, and a `category` outside the known ones, replaced by their length, or `web server`), version + `git describe --always --dirty` (run with `GIT_OPTIONAL_LOCKS=0`, so it never takes `.git/index.lock`), Python, platform, pid; CLI end line `end: exit N after S s`, traceback of an exception a command does not handle; Flask's request tracebacks and werkzeug request lines reach it through the root logger; `threading.excepthook` logs uncaught thread exceptions; the web log gets `end: web server stopped` from an `atexit` hook at a normal exit (a killed server writes none). Same file again in one process: handler kept; a web app created inside a CLI command (`translate.py review`) keeps `cli.log` (the command's start/end lines stay together; no web end line); the path is absolute; a file that cannot be opened: warning on stderr, the program goes on. The root logger passes INFO and up from every logger, third-party ones included (werkzeug, the Copilot SDK runtime's stderr): not filtered, they are often the clue. Terminal: `proclog.terminal` keeps what the terminal showed before the file handler (CLI: WARNING+ bare message, as `logging.lastResort`; web: INFO+ with time), unless another handler owns the root logger (pytest, an embedding program). May contain book text (project names, URLs with terms, backend error messages quoting model output; only the Copilot backends mask e-mail addresses, `claude-cli` masks nothing): local only. `logs/` is in `.gitignore`.
- **Event record** (`src/core/events.py`): `<project>/log/events.jsonl`, one JSON object per line, appended with one `os.write` on an `O_APPEND` file under a per-path lock (whole lines across threads and processes; a cut-off last line is ended with a newline first). `append_record` never raises (logs a warning; a short `os.write` is reported); it never creates the project directory, and a run stops writing once its record was set aside (`set_aside`) or its project deleted (`retire`: an in-process generation per path that `RunEvents` captures at creation; the web delete retires and removes the directory under the record's lock, `events.retired`, so an append already past its checks finishes first). Every line: `v` (1), `ts` (UTC, ms), `run` (`<UTC start>-<6 hex>`), `source` (`web`, `cli`, `retranslate`, `extract`), `event`; None fields left out. Events: `run_start` (workers asked for, segments, mode, backend/model/effort/timeout), `call`, `segment` (result `translated`/`failed`/`dropped` + reason `edited_before_call`/`edited_during_call`/`project_replaced`, model, calls, split, issue codes of a failure or warning codes of a translation), `pause` (reason `user`/`rate_limit`/`auth`/`backend_unavailable`, error class, resume_in), `wait_extended`, `resume` (reason `user`/`auto`), `run_end` (state `completed`/`stopped`/`failed`/`interrupted`, counts, seconds, error class; extraction: terms, added). `call` fields: kind (`request`, `retry` = feedback follow-up, `split`, `extract`, `consolidate`; a transient retry repeats the kind it retries), segment, attempt (1–`MAX_CALLS` within the segment's budget), backend, model, effort, timeout, seconds, tokens_in/out (when the backend reports usage; never for `claude-cli`), chars_in/chars_out, outcome (`accepted`, `rejected` + `issues` codes, `truncated`, or `error_outcome(exception)`: `cancelled` (also Ctrl-C, `KeyboardInterrupt`), `rate_limit`, `auth`, `backend_unavailable`, `refusal`, `timeout` (`CallTimeoutError`, a `TransientError` raised by `CLIBackend` and `CopilotSDK` on their deadline), `transient`, `error`, `unexpected`), `warnings` codes, `error` class name. No book text: never source, translation, prompt, reply, glossary term or error message. Hooks: `TranslationEngine(events=…)` → `_Session.call` records an exception at once and a reply after its check (`_Session.checked`, from `attempt`); `TranslationOutcome`/`Reply`/`TranslationError` carry `calls` and `split` (not compared); `TermExtractor(events=…)._call` (recorded once its reply is parsed, `_parsed`: an unreadable reply is `rejected` with `unusable_reply`, Ctrl-C while reading it `cancelled`; no model given records the backend's default model, the request still passes none); a reply whose cleaning or check raises is recorded with the error's outcome (`_Session.unchecked`), and an unexpected outcome carries the calls made; runs: `TaskManager` (`_start_locked` run_start, `_apply_result` → `_record`, `pause_translation`, `_pause_for`, `resume_translation`, `_end_record`: run_end once, before the end is published (state, SSE event, lock release; a failure's `failed` state too; the one exception: a user's stop shows `stopped` from the request itself, the record's run_end follows when the calls in flight end; a pause after the last result ends `completed`, and once `task.finishing` is set pause/resume change nothing); a coordinator or extraction thread that cannot start writes a failed run_end), the retranslate endpoint, the web extraction thread, CLI `_Run` (in `_start`) and `glossary extract` (run_end after the glossary is saved: `added` = terms stored, new or replaced; a failed save is `failed`). The web run_start is emitted before `task.events` is set, so a start that fails before it writes no run_end; the pause line is written inside the locked transition. Segment ids come from the EPUB's chapter ids (`known-issues.md`). No rotation (~300 bytes per call). A web project replaced by name gets a fresh record: the old one is moved to `log/events-<UTC time>.jsonl` (`set_aside`, kept; a failure to move it is logged and the new book's stats then include the old runs).
- **Summary** (`src/core/stats.py`): `project_stats(project_dir, since, run)` → `read_records` (skips and counts lines that are not JSON objects with `event`/`run`/`ts` of version 1, or have a known field of the wrong type: `shape_problem`, shared with `run_records_check`) → `summarize`: per work (`translation`, `extraction` = calls of kind extract/consolidate) and backend/model/effort (`models`): calls, outcomes, rejected issue codes, `seconds_median`/`seconds_p90` (nearest rank, both over the calls that returned a reply: accepted/rejected/truncated, counted in `seconds_calls`; a cancelled call, a quick error or a timeout would skew them), `timeouts`, tokens (None when no call reported them), and the segments whose last call was there: `first_attempt` (translated with 1 call), `more_calls` (translated with more, including transient retries), `split` (those of `more_calls` that were split), `failed` and their shares; `rejected_issues`, `failure_issues`, `warnings`; `runs` (start, end, duration (a finished run: its run_end `seconds`), state, error, counts, pauses, calls; no `run_end` → `unfinished`); `records`, `skipped_lines`, `exists`. `translate.py stats` prints `text_report` or `--json` (the same dict); `--since` is an ISO date/time, local unless it has an offset (out of range: usage error / 400). The web endpoint returns the same dict.

### Project data (`projects/<name>/`, not in git)
- `project.json`: `schema` 2 for new projects (project-level `source_sha256` and absolute `epub_path`; segments with `block_start`/`block_end`/`fingerprints`). `backend`, `segmentation`, `brief`, `effort`, `timeout` are omitted when absent (None: the default — effort `low` for a model that takes levels, none otherwise; timeout 180 s), so older files round-trip; load refuses an `effort` outside `KNOWN_LEVELS` or a `timeout` outside 30–3600; a missing `model` is filled with the backend's default on load and written by the next save. Status: `pending`, `translated`, `reviewed`, `failed`.
- Schema 1 (pre-plan projects) translates but cannot be exported or validated: `translate.py migrate` (`src/core/migrate.py`) once. Needs the source EPUB (`source_epub_path`: `source.epub`, else `epub_path`); refuses when `project.schema1.json` exists or the project is locked; changes no project data unless every chapter matches (the lock file is still created). A merged group with a pending/failed/empty member keeps no translation (the old text stays in `project.schema1.json`): read the dry run's notes first. Copies `source.epub` when missing.
- Web `POST /api/projects` replaces an idle project of the same name (new `project.json` and `source.epub`, `log/failed/` removed, `log/events.jsonl` set aside as `events-<time>.jsonl`, `glossary.json` kept); CLI `init` refuses an existing one. Known issue: "idle" means no translation task; a web export of that project running in the same server is not refused (the lock is shared by the server's threads), so its result should be discarded (`known-issues.md`).
- Also `glossary.json`, `source.epub`, `log/events.jsonl` (event record), `log/translation_*.log` (web runs), `log/failed/`, `output/*.epub`. Beside `projects/`: `logs/web.log`, `logs/cli.log` (process log).

### Glossary (`src/glossary/`)
- Entries: term, translation, category (`person`, `place`, `work`, `organization`, `term`, `expression`, `other`), and for people `gender` and `note`, which go into text prompts. Prompt rule 5: a person name in the glossary is written as the glossary gives it (Chinese, or English when that is the translation; a surname or given name alone of a listed full name, whoever bears it, takes the matching part, English when it cannot be matched), any other name (also a well-known person) or unlisted part stays in English; titles are translated. Past 150 entries a segment naming a person only by part of a listed full name does not get the entry (`known-issues.md`). All entries are in the prompt up to `FULL_GLOSSARY_MAX_TERMS`=150, else only those found in the segment.
- `TermExtractor.extract_from_segments` (the project's timeout and effort per call): batches of ≤5000 chars propose terms; terms proposed with several translations are decided by consolidation calls; undecided ones keep the most frequent proposal. A rate limit, login error or unavailable backend stops it with the terms found so far (kept). The web adds only terms not yet in the glossary; `glossary extract` (CLI) also replaces the translation and category of existing ones but keeps their gender/note.

### Web (`src/web/`)
Flask app factory (`server.py`, `create_app(projects_dir=None)`), one blueprint per area, Jinja2 + Alpine.js 3 (no build step). Alpine calls a component's `init()` itself: do not add `x-init="init()"`.

Pages: `/`, `/new`, `/project/<name>` (`/overview`, `/glossary`, `/translation`, `/review`, `/review/chapter/<chapter_id>`, `/search`, `/export`, `/stats`); `?issues=1` on review pages shows only segments with issues. `/stats` (`blueprints/stats.py`, `templates/project/stats.html`) shows `GET …/stats` as plain tables (per backend/model/effort, issue codes, runs), the skipped line count and an empty state; it only reads the event record, so it works during a run; a reload button, no live update.

API (`/api/...`):

## Testing and verification

- `python3 -m pytest tests/ -q -p no:cacheprovider -rfw` — must pass with no warnings, also when several suites run at once. New tests wait on conditions (`_wait`, events), not on sleeps (a few older timing tests still sleep). No test makes a real model call: besides the two guards above, a measuring script that imports `run_process` by name must be added to `MEASURING_SCRIPTS` in `tests/test_verify_scripts.py`, whose autouse fixture makes that copy fail unless a test stubs it.
- `scripts/verify/mutation.sh [BASE] [MAX_CHILDREN [FILE...]]` — (MAX_CHILDREN caps mutmut's workers, default one per core, e.g. `4` to bound memory and CPU; FILE... limits the run to those files of the list) mutmut 3.8.1 over the lines changed vs `BASE` in the files listed in `mutation.py`, on a copy of the tree. Runs on the active environment's `python3` (the project venv with both requirements files). Exits 2 when mutmut is missing or no eligible line changed.
- `scripts/verify/` — one script per phase claim, each with a docstring:
  - read-only checks of real projects (`--projects-dir`, never written): `phase0_code_segments`, `phase1_load_projects`, `phase2_roundtrip`, `run_records_check` (event records, every line read itself: a line that is not JSON is counted, a JSON line of the wrong shape FAILs; per-event required fields (a translation call also segment and attempt), field types, string values from closed sets only (reported by field and length, never text; lines and runs by position), segment ids of the project, run counts add up) read in place; `phase2_migrate_copies`, `phase3_export_check`, `phase4_validate_check`, `phase5_glossary_check`, `phase6_segmentation_check` work on a temp copy. `--anonymize` covers stdout only: a file written with `--sample-out` (phase5) or `--out` (phase8) holds real book text and must never be published or committed;
  - guards of the test suite itself: `phase1_reverts` (old behaviours put back one by one; each must fail a test) and `phase1_survivor_kills` (recorded mutants must be killed); both work on `git archive HEAD`, so commit first;
  - measurements that make REAL model calls (cost quota, run only on purpose): `phase7_cli_overhead`, `phase7_throughput`, `phase8_brief_sample`, `phase8_extraction_compare`, `phase9_copilot_overhead`, `phase10_effort_check` (CLI backends), `phase12_sdk_check` (the SDK backend: concurrency, runtime restart, effort, cancel/timeout abort without usage, session deletion, no process left; it reaches the runtime only through `copilot_sdk._new_client`).

## Troubleshooting

- To stop a run: the web pause button (saved at the next tick), or Ctrl-C in the CLI's terminal (kills the calls in flight, then saves). Killing the web server loses results not yet saved.
- A call left behind: pause / Ctrl-C first; then `pgrep -fl 'claude -p'` (or `copilot -p`; the SDK backend's runtime is `copilot --headless`), check that it is this project's, `kill <PID>` (killing `copilot --headless` leaves the session folders of its calls in flight). Not `pkill -f`: it also hits other sessions. Process arguments contain book text: do not paste them anywhere public.
- Translation and extraction calls time out after the project's timeout (default 180 s; `model set -t` or the translation page); a high effort on a slow model can need more. A timeout is a transient error, retried within the segment's budget: a retry that succeeds leaves no segment failure and no failure file (the web run log keeps a warning). Only when the budget is used up does a pending segment become `failed` (`log/failed/`; retry with `start --retry-failed` or the retry button); a translated/reviewed one keeps its text and status and only gets issues (retranslate it from review/search). Term extraction does not retry: a timed-out batch is logged and proposes nothing, a timed-out consolidation call leaves its terms at the most frequent proposal. Stored translations that fail the check: `validate --mark-failed`, then `start --retry-failed`.
- "project locked" (409 / CLI message): another process (a CLI run, the web task, an export, a migration) holds `project.lock`.
- Export or validate refuses a schema 1 project: run `migrate` first.
- Export cannot read the source EPUB ("無法讀取來源 EPUB"): the project's `source.epub` is missing (removed or renamed) and the recorded `epub_path` does not lead to the book either; put the book back as `source.epub` in the project directory. A hash mismatch means that file is not the book whose digest was recorded at creation or migration.
- Copilot run stopped with "無法確認 Copilot CLI 已套用翻譯用的系統提示": the plugin did not load or the CLI changed; check `copilot --help` for `--experimental`/`--plugin-dir`.
- Web run log: `projects/<name>/log/translation_*.log`. Process log: `logs/web.log`, `logs/cli.log` beside `projects/` (start lines with version and pid, request lines, tracebacks). What happened in a run: `translate.py stats -p DIR` (or the web stats page), then `--json` / `log/events.jsonl` for single calls, then the process log around those times.
